## What Anthropic says causes generic output, and the frontend-design skill's rules

### Takeaway
Anthropic's stated cause is "distributional convergence": without direction the model samples the safe, high-probability centre of its training data. The fix has moved from "be bold, avoid Inter and purple gradients" (2025) to a design-studio brief: ground the design in the subject, name the specific AI tells to avoid, plan a token system, check the plan against "what would I do for any similar page", then build and critique with screenshots.

### Cited Findings
- Blog post "Improving frontend design through Skills", 12 Nov 2025, by Prithvi Rajasekaran, Justin Wei, Alexander Bricken (Applied AI). Names distributional convergence as the cause; the model drifts to "this high-probability center" without direction. Named defaults: Inter, purple gradients on white, minimal animation. — [Claude blog](https://claude.com/blog/improving-frontend-design-through-skills)
- Same post: a ~400-token aesthetics prompt in four dimensions (typography, colour/theme with CSS variables, motion as one orchestrated page load with staggered reveals, layered backgrounds) plus an avoid list. Notes Claude still converges on Space Grotesk even when told to avoid others. Each dimension can be steered on its own (a typography-only instruction alone gave a big lift; a theme like "RPG aesthetic" gave a distinct style). Advises prompting at the right altitude: not exact hex codes, not vague. — [Claude blog](https://claude.com/blog/improving-frontend-design-through-skills)
- Why a skill rather than a system prompt: a skill is a markdown file loaded only when the task needs it, so design guidance doesn't burden unrelated work. Also describes a `web-artifacts-builder` skill (React, Tailwind, shadcn/ui, bundled with Parcel). Before/after examples: SaaS landing page, blog, admin dashboard. — [Claude blog](https://claude.com/blog/improving-frontend-design-through-skills)
- The skill lives at `anthropics/skills/skills/frontend-design/SKILL.md` (Apache 2.0). Commit history: Dec 2025 (original), 9 Jun 2026 rewrite (#1293), 3 Sep 2026 update "to avoid generic design defaults" (#1713). The `anthropics/claude-code` plugin copy was updated 18 Jun and 2 Sep 2026, then on 26 Oct 2026 plugins moved to the `claude-plugins-official` marketplace. — [anthropics/skills](https://github.com/anthropics/skills/tree/main/skills/frontend-design); [anthropics/claude-code commits](https://github.com/anthropics/claude-code/commits/main/plugins)
- **Original (Dec 2025) skill**: "commit to a BOLD aesthetic direction"; pick an extreme tone (brutalist, maximalist, retro-futuristic, luxury, etc.); avoid Inter, Roboto, Arial, system fonts, purple-on-white gradients; never converge on Space Grotesk; use gradient meshes, noise, grain, custom cursors; scroll-triggered and surprising hover states. — [skill @ 00756142](https://github.com/anthropics/skills/blob/00756142/skills/frontend-design/SKILL.md)
- **Current (Sep 2026) skill**, framing: act as design lead at a studio known for giving each client an identity "not mistaken for anyone else's"; the client has already rejected cliché proposals. — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Current skill rules (paraphrased):
  - **Ground in the subject.** If the brief doesn't name the product, audience and primary job, propose them and confirm. Distinctive choices come from the subject's industry, materials and vernacular. Use the brief's real content throughout.
  - **Hero.** Open with the most characteristic thing in the subject's world. The big-number + small-label + stats + gradient hero is "the default treatment"; use only if truly best.
  - **Typography.** One or two families, clearly distinct if two; not the families you'd use on any other project; a clear type scale following *The Elements of Typographic Style*; line length under 80 characters; extra line-height for serif body.
  - **Typographic tells to avoid**: one accented word in a headline (italic, bold or colour), all-caps labels, unneeded labels above content.
  - **Structure is information.** Borders, numbering, eyebrows, dividers must encode something true. Numbered 01/02/03 markers only for a real sequence.
  - **Motion.** Sparse and deliberate; one orchestrated moment beats scattered effects. Fade-and-slide-up on each section and hover transitions on every card "read as AI-generated". Motion that answers a user action is welcome.
  - **Copy** can make a design feel as templated as the visuals.
  — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Current skill's calibration list: AI design clusters around five traits: (1) warm cream ~#F4F1EA, high-contrast serif display, terracotta accent (~#D97757, which the skill says is Anthropic's own accent and "reads as a tell"); (2) near-black with one acid-green or vermilion accent; (3) broadsheet layout with hairline rules, zero radius, dense columns; (4) the SaaS card kit: identical rounded cards, one radius everywhere, the same soft grey shadow rgba(0,0,0,.1), gradient washes; (5) template chrome: tracked ALL-CAPS eyebrow over every heading, "A · B · C" meta strings, "WORD — fragment" labels, #0B0B0B/#111 for black, monospace for small data labels, "→" appended to links and buttons. The brief's own words win, even if it asks for one of these; where the brief leaves an axis free, don't spend it on a default. — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Current skill's process: two passes. Plan a compact token system (4–6 named hex colours; typefaces and roles; layout concept in one-sentence prose plus ASCII wireframes, with alignment; principles). Then review the plan against the brief: if any part is what you'd produce for any similar page, revise it and say why. Only then code. Watch CSS specificity clashes (e.g. `.section` vs `.cta` padding). — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Current skill on restraint: "Spend your boldness in one place": one memorable element, everything else quiet. Quality floor without announcing it: responsive to mobile, visible focus, reduced motion, accessible, harmonious colour. Critique as you build with screenshots ("a picture is worth 1000 tokens"); Chanel's remove-one-accessory rule; keep notes on what you've tried so later passes do something new. — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Current skill on writing: words exist to make the UI easier to use; name things in the user's terms; active-voice CTAs ("Save changes", not "Submit"); keep an action's name through the flow ("Publish" → "Published"); errors explain the fix and don't apologise; empty states invite action; sentence case. — [current SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)
- Change between June and September 2026 versions: June version asked for "one real aesthetic risk" and a single "Signature" element in the plan, and a characterful display face plus body plus utility face; September version drops the forced extra faces (one family is fine), adds the explicit typographic-tells list, the SaaS-card and template-chrome traits, the #D97757 note, the line-length rule, and the instruction to confirm the inferred subject with the client. — [diff of 2235be7c vs main](https://github.com/anthropics/skills/commits/main/skills/frontend-design/SKILL.md)
- Engineering post "Harness design for long-running application development", 24 Mar 2026 (Prithvi Rajasekaran): a generator/evaluator (GAN-like) loop for frontend design. Four criteria given to both agents: design quality, originality (penalises templates, library defaults, AI patterns such as purple gradients over white cards), craft, functionality. Design and originality weighted higher because Claude already did craft and functionality well but was "bland at best" on the other two. The evaluator used Playwright MCP to navigate the live page, take screenshots and critique; 5–15 iterations, up to four hours. Key finding: agents "reliably skew positive when grading their own work", so a separate, tuned evaluator works better. Example: a Dutch art museum site that at iteration 10 abandoned a polished dark landing page for a CSS-3D gallery room. — [Anthropic Engineering](https://www.anthropic.com/engineering/harness-design-long-running-apps)

### Inferences
- Anthropic's own advice has shifted from adjectives ("bold", "unforgettable") to named, checkable anti-patterns plus a plan-then-audit step. The 2025 skill's own suggestions (gradient meshes, grain, staggered reveals, hover surprises) are now partly on the 2026 skill's list of AI tells: the remedy itself became a default.
- The "would I do this for any similar page?" test and the separate-evaluator finding both argue for a review step that is not the builder judging its own work.

### Gaps
- No published eval numbers showing how much the 2026 skill rewrite improves output; only qualitative before/after in the 2025 post.
- I did not fetch the current `claude-plugins-official` copy of the plugin to confirm it is identical to `anthropics/skills`.

## Anthropic prompting docs: per-model design behaviour (Opus 5.5, Fable 5.2, Sonnet 5.5, and the 4.x/5 line)

### Takeaway
Anthropic now documents a model-specific "house style" and says generic "don't look like AI" instructions just swap one default for another. What works: name the specific patterns to avoid, give a concrete alternative spec, or have the model propose several directions and let the human pick. Opus 5.5 has a dedicated frontend section; Fable 5.2's guide has none; Sonnet 5.5's guide has none but points back to Sonnet 5's.

### Cited Findings
- General best-practices page (covers Fable 5.2, Mythos 5.2, Opus 5.5, Sonnet 5.5 and back to Opus 4.6/Sonnet 4.6, Haiku 4.5) still carries the Opus 4.5/4.6-era "Frontend design" section: without guidance models default to "what users call the AI slop aesthetic", plus a long `<frontend_aesthetics>` system-prompt snippet (typography, colour/theme "draw from IDE themes and cultural aesthetics", motion, backgrounds, avoid list, Space Grotesk warning). Points to Claude Design for canvas work. — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- Same page: Opus 4.5/4.6 vision improved, reads screenshots and UI elements more reliably in computer use; giving Claude a crop/zoom tool gives "consistent uplift" on image tasks. — [Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
- **Opus 4.8**: "strong design instincts" with a consistent house style: warm cream/off-white (~#F4F1EA), serif display (Georgia, Fraunces, Playfair), italic word accents, terracotta/amber accent. Good for editorial, hospitality, portfolio; poor fit for dashboards, dev tools, fintech, healthcare, enterprise. The default is persistent: "don't use cream" or "clean and minimal" shifts it to another fixed palette. Two fixes: (1) give a concrete alternative spec (a full worked example: palette hexes, 4px radius, typeface character, section order, hover timing); (2) "propose 4 distinct visual directions (bg hex / accent hex / typeface + one-line rationale), user picks one, implement only that". Says Opus 4.8 needs less prompting than earlier models and offers a one-paragraph `<frontend_aesthetics>` snippet instead of the long skill. — [Prompting Claude Opus 4.8](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-4-8)
- **Sonnet 5**: same advice as Opus 4.8, but no house style named: it "might settle into a consistent default visual style". Because `temperature` returns a 400 error on Sonnet 5, propose-directions-first is "the recommended way" to get variety across runs. — [Prompting Claude Sonnet 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5)
- **Opus 5.5** (released 22 Sep 2026): section "Frontend design defaults". Without design direction it "falls back on a few default styles"; a general "avoid a generic AI look" mostly swaps one default for another. It responds well to naming specific patterns. Example: no cream/off-white background, no italic accent words in headlines, no numbered 01/02/03 section labels, no monospace labels, no pill-shaped buttons. Work iteratively: check which styles the first result used instead and extend the list. — [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- Opus 5.5 vision: reads charts, diagrams and screenshots more accurately than Opus 5 even at lowest effort; better where meaning depends on position (which boxes an arrow joins, what changed between two diagram versions); more reliable computer use from screenshots. For the densest inputs, higher-resolution images and crop/zoom tools (PIL/OpenCV in a container, or the crop-tool recipe) still help, more so at higher effort. — [Prompting Claude Opus 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)
- Opus 5.5 announcement (22 Sep 2026): top scorer in a one-prompt game build "on the strength of its graphics and polish", ahead of Fable 5.1; customer quotes on denser slides and a design spec "usable with very minimal edits" (Ramp); Chartography visual chart recognition 89.0% vs Fable 5.1 88.4%. No dedicated design or aesthetics benchmark. — [Anthropic news](https://www.anthropic.com/news/claude-opus-5-5)
- **Fable 5.2** (released 9 Nov 2026): its prompting guide has no frontend or design section. Relevant points: it follows style rules closely (hard writing limits can make prose choppy); treats "never" as absolute; at `xhigh`/`max` it used subagents to review its own work, which Fable 5.1 did not; early testers liked it as planner/orchestrator for other models; review prompts, skills and memory written for Fable 5.1 or Opus 5.5 before migrating. — [Prompting Claude Fable 5.2](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2)
- **Sonnet 5.5**: no frontend section. Relevant: adds unrequested tests and files; at `low` effort may report done without a real check (gives a "run a real check" prompt); for dense charts and technical drawings, crop/zoom tools help more than raising effort; "For the hardest long-horizon work, an Opus model is the better choice". — [Prompting Claude Sonnet 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5-5)
- Third-party (not Anthropic): a muz.li piece says the Opus 5.5 system card does not test design at all, so design evidence is anecdotal; a ChatPRD review calls Opus 5.5 the go-to for complex frontend in SaaS/dev tools but not consumer app design; TechCrunch/Betanews and Digital Trends disagree on the size of the Opus 5.5 price cut (20% vs 40%). — [muz.li](https://muz.li/blog/claude-opus-5-5-for-designers/); [ChatPRD](https://www.chatprd.ai/how-i-ai/claude-opus-5-5-review); [TechCrunch](https://techcrunch.com/2026/09/22/anthropic-releases-opus-5.5-with-lower-prices-and-fable-level-performance/)
- Third-party (not Anthropic): Fable 5.2 launch coverage says improvements in coding, reasoning and vision and ~30% faster output; a UX Planet test found Fable 5.2's mobile-app design much better than Fable 5.1's but worth using only in specific cases (one run took 27 minutes). — [9to5Mac](https://9to5mac.com/2026/11/09/anthropic-upgrades-claude-with-new-fable-5-2-model-details-here/); [UX Planet](https://uxplanet.org/claude-fable-5-2-for-ui-design-better-but-at-what-cost-81aeec4170f4)

### Inferences
- The cream/serif/terracotta look named as Opus 4.8's house style is the same trait (1) the current skill flags; Opus 5.5's own example avoid list (cream, italic accents, 01/02/03, monospace labels, pills) maps onto traits (1) and (5). So for Opus 5.5 the skill's calibration list doubles as the documented default to steer away from.
- A design brief for a project with a fixed look (like a written plate) is the "concrete alternative spec" route, which the docs say the model "follows precisely". Generic anti-slop wording is the route the docs say fails.
- Fable 5.2 appears to have no documented design default; I found no Anthropic statement either way.

### Gaps
- No official Anthropic statement on Fable 5.2's design or front-end defaults or quality; only third-party anecdotes.
- No Anthropic design benchmark comparing Opus 5.5, Fable 5.2 and Sonnet 5.5 on UI aesthetics.
- I did not read the Opus 5 or Opus 4.7 prompting guides directly; the best-practices index lists "design and frontend defaults" only for Opus 4.8 and Sonnet 5.

## Claude Design: what it is, design systems, handoff to Claude Code, limits

### Takeaway
Claude Design (Anthropic Labs, launched 17 Apr 2026 on Opus 4.7) is a chat-plus-canvas tool for designs and prototypes. Since 17 Jun 2026 it imports design systems from a repo, files or uploads, checks output against them, and syncs both ways with Claude Code via `/design-sync` and `/design`. It now runs inside normal Claude and shares the plan's usage limits; the standalone claude.ai/design closes 14 Dec 2026.

### Cited Findings
- Launch 17 Apr 2026, research preview for Pro, Max, Team, Enterprise; powered by Opus 4.7 ("most capable vision model" at the time). Onboarding builds a team design system by reading your codebase and design files; later projects use its colours, type and components. Inputs: prompts, images, DOCX/PPTX/XLSX, codebases, a web-capture tool. Export: org URL, folder, Canva, PDF, PPTX, standalone HTML; a "handoff bundle" passes to Claude Code with one instruction. — [Anthropic news](https://www.anthropic.com/news/claude-design-anthropic-labs)
- 17 Jun 2026 update (updated Sep 2026): import one or several design systems from a GitHub repo, design files or raw uploads; admins can approve one standard and lock edits; Claude builds with your components and checks output against the system before you see it. `/design-sync` pulls a design system in from Claude Code; `/design` creates, edits and syncs design projects from Claude Code; handoff continues from the design work "instead of starting from a screenshot". New editor (drag, resize, align). Exports PDF, PowerPoint, HTML; connectors Adobe, Base44, Canva, Gamma, Lovable, Miro, Replit, Vercel, Wix. Shares limits with Claude Code. Sep 2026: works in any Claude conversation, Claude Code and the Artifacts tab. — [Claude blog](https://claude.com/blog/claude-design-stays-on-brand-for-daily-work)
- Help-centre article: available on Free, Pro, Max, Ultra, Team, Enterprise. Same usage pool as the rest of Claude; earlier separate weekly allowance retired. "Design system import is only as good as its source": a messy codebase carries through. Enterprise on by default from 15 Oct 2026; standalone claude.ai/design closes 14 Dec 2026. — [Claude Help Centre](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)
- Known limits listed there: no version history yet (ask Claude to save state before a new direction); inline comments sometimes fail to appear; very large repos lag (link from Claude Code instead); basic multi-person editing; sharing can't be changed on mobile apps; adding text layers or artboards needs mouse/trackpad. — [Claude Help Centre](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)
- Third-party: VentureBeat framed the June update as fixing a "token burning problem"; other outlets say token cost still slows the workflow. — [VentureBeat](https://venturebeat.com/technology/anthropic-ships-major-claude-design-overhaul-with-design-system-imports-code-round-trips-and-a-fix-for-its-token-burning-problem); [TechRepublic](https://techrepublic.com/article/news-anthropic-claude-design-overhaul-enterprise-teams)

### Inferences
- Claude Design's "check output against your design system before showing it" is the same plan-then-audit idea as the skill, but enforced by the product against an imported system.
- Because it shares the plan's usage pool, it costs no extra money on a subscription but heavy iteration eats the same limits as Claude Code.

### Gaps
- The help article does not name which model powers Claude Design today (launch said Opus 4.7).
- Whether Figma files import directly is not stated in the help article.

## Claude Code docs: skills, hooks, subagents and screenshot verification in a design workflow

### Takeaway
Claude Code's docs say: give Claude what it can't see (paste the design screenshot), give it a check that returns pass or fail (a browser screenshot next to the mockup counts), ask for evidence (the screenshot), and use hooks only for rules with zero exceptions. Anthropic's own harness research adds: use a separate evaluator, not self-grading.

### Cited Findings
- Hand over what Claude can't see: "paste the screenshot of the design" into the prompt. Say "be ambitious" when you want empty and error states, keyboard navigation and wiring, not just the layout. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- Give Claude a check to run; listed options include a test, build exit code, linter, fixture diff, and "a browser screenshot next to the mockup" (via Claude in Chrome). Strictness ladder: in the prompt → `/goal` (a separate model checks the condition every turn) → a `Stop` hook (harness-enforced) → `/code-review` in a fresh subagent. Ask for evidence: the command output "or the screenshot". After "done", `/verify` has Claude build and run the app and look at the result, catching what tests miss. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- Guidelines vs enforcement: CLAUDE.md and skills are guidance Claude may judge inapplicable; hooks, deny rules and managed settings are deterministic. "If something has to happen every time, make it a hook". Keep the enforced set small. Piling on IMPORTANT/ALL CAPS makes current models over-apply rules. — [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
- Separate evaluator pattern: Anthropic's harness research found self-grading skews positive; a separate evaluator with Playwright screenshots, scoring against written criteria, gave better design over 5–15 rounds. — [Anthropic Engineering](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- Skills load only when relevant, which is why Anthropic ships design guidance as a skill rather than in the system prompt. — [Claude blog](https://claude.com/blog/improving-frontend-design-through-skills)

### Inferences
- A design workflow built from these pieces: a project skill holding the look (concrete spec, avoid list); a screenshot check against the approved picture; a reviewer that didn't build the screen; a hook only for hard rules (e.g. no hard-coded colour outside the token file).

### Gaps
- I did not read the dedicated Claude Code pages on output styles, subagents or the Chrome integration; I found no Anthropic doc that ties output styles to design work.
